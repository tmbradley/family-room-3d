# Room scanning: how it works

The iPhone setup is in `ios/README.md`. This file covers the server side.

## Flow

1. **Pair** (Michael's passkey session only): `POST /api/upload-tokens` with either
   `{roomId}` (rescan a Current room) or `{newRoom: true, label}`. The response is a code like
   `ABCD-EFGH-JKLM`. Only its SHA-256 is stored. The code lasts 60 minutes, allows 24 files
   (JSON + USDZ + up to 20 photos) and is good for one import. The editor's **Pair phone** button
   does this and shows a QR code for `https://<host>/scan?token=<code>`, which opens the House
   Planner app (universal link). `{placementId}` makes a *model* code instead (Capture this piece:
   2 files, one USDZ/GLB attached to that placement by `POST /api/models/import`).
2. **Upload** (code only): `validate`, then `uploads/presigned`, a PUT to the bucket, and
   `uploads/:id/complete` (photos carry `{prompt, note, roomTag, tags}`). Each upload row stores its
   `token_id`; each photo gets a `scan_photos` row. Completing or importing
   someone else's upload is refused (403), as is going over the limit (429).
3. **Import** (code only): `POST /api/scans/import {token, uploadId, roomplanData}`.
   - The upload must belong to the code and be a completed `roomplan_json`.
   - The room must match the code's scope.
   - The JSON must be Apple's `CapturedRoom` Codable format.
   - Optional `objectLabels` (RoomPlan object identifier → short label from the phone).
   - The result is a **pending** scan import, and the code is spent. Every photo sent with the code
     is linked to the scan import (and its room).
   - Until it expires, the same code can send measurement notes: `POST /api/upload-tokens/room`
     (outline with ids) and `POST /api/suggestions` (max 5 batches) create a pending proposal.
4. **Review** (anyone with read access): `GET /api/scans`, `GET /api/scans/:id`. The response
   includes `preview`, which the editor draws next to Current.
5. **Promote / Reject** (Michael only): `POST /api/scans/:id/promote` and `/reject`. Agent keys
   get 403. Promote:
   - writes one `rescan` revision to Current;
   - records every scanned value as a `source = scan` measurement;
   - for a rescan, matches walls and openings to the existing ones (alignment plus endpoint
     distance), so ids, pins and furniture survive;
   - always keeps pinned values;
   - keeps unmatched walls that have pins, fixtures or a fireplace.
6. **Undo:** `GET /api/current/history`, `POST /api/current/rollback {toRevision}` (Michael
   only). The rollback is a new revision that reverses the later ones and skips pinned fields.

Current changes only through promoted scans, measurements and rollbacks. Editor saves and
proposals cannot target it.

## Parser (`server/scans.ts`)

It reads `walls`, `doors`, `windows`, `openings`, `floors` and `objects` from a `CapturedRoom`:

- `category` is a keyed enum, e.g. `{"door":{"isOpen":false}}`.
- `dimensions` are in metres: `[length, height, 0]` for surfaces and `[w, h, d]` for objects.
- `transform` is a column-major 4×4. Columns 0–2 are the axes and 12–14 the position; y is up.
- `parentIdentifier` (iOS 17) links an opening to its wall. Without it, the nearest wall is used.

The plan uses x = world X and y = **−world Z**, in inches (`plan_frame = 2`). Scans imported before
this fix used y = +world Z, which drew the room mirrored; they have `plan_frame = 1`, and Current
rooms built from them are flagged in the editor with a Michael-only *Fix mirror* button
(`POST /api/rooms/:id/fix-mirror`, one rollback-able revision). It is rotated so the walls are square to the
axes and shifted to start at 0. The fixture is `fixtures/sample-roomplan.json`, generated by
`fixtures/make-sample-roomplan.mjs`. It is synthetic but in the real layout. The tests also use
a wall copied from a published CapturedRoom sample.

## Server configuration

- Bucket: `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`.
  These are the same as the backups use.
- `APPLE_TEAM_ID` (set to `Q3HHMS5MLX`): `/.well-known/apple-app-site-association` lists
  `applinks` for `Q3HHMS5MLX.com.michaelbradley.houseplanner` on `/scan?token=` links. There is no
  App Clip any more.

## Photos, templates and models

- Photos: `GET /api/photos?roomId=|scanImportId=` (session or read-scope agent key) returns each
  photo with a signed URL valid 10 minutes. MCP: `list_room_photos`, `get_scan_import`.
- Furniture templates (14 types, `GET /api/templates`, MCP `list_templates`): parameters are rows
  in `template_params`; placements store values in `placement_params`. Scanned objects map to the
  closest template by category and size.
- Models: a USDZ/GLB attached to a placement wins over the template. The web viewer loads it with
  three.js (`USDLoader` for USDZ, `GLTFLoader` for GLB) through `/api/models/:id/file`; if loading
  fails it draws the template with a "custom model" badge.

## Tests

`npm test` runs only against `TEST_DATABASE_URL`. The database name must contain "test" and
must not be a Railway host. The tests refuse a non-empty database they did not create.
